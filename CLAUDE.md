# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Проект

WordCards — веб-сервис для изучения иностранных слов на Django 6 (Python 3.14, SQLite). Серверный рендеринг через Django templates + Bootstrap 5 по CDN; без REST API и JS-фреймворков. Интерфейс на русском языке.

## Команды

Виртуальное окружение — `venv/` в корне. В PowerShell:

```powershell
venv\Scripts\activate            # активировать окружение
python manage.py runserver       # запустить dev-сервер (http://127.0.0.1:8000/)
python manage.py makemigrations  # создать миграции
python manage.py migrate         # применить миграции
python manage.py test            # все тесты
python manage.py test accounts   # тесты одного приложения
python manage.py check           # проверка конфигурации
```

Без активации окружения можно вызывать напрямую: `venv\Scripts\python.exe manage.py ...`

## Архитектура

- Проект `wordcards/` (settings, корневой urls); приложения: `accounts/` — аутентификация и пользователи, `courses/` — курсы и карточки слов.
- **Кастомная модель пользователя** `accounts.models.User` (наследует `AbstractUser`), подключена через `AUTH_USER_MODEL = 'accounts.User'`. Ключевое поле — `role` (`TextChoices`): `creator` (создатель курсов) или `student` (ученик). Во всех ссылках на пользователя использовать `settings.AUTH_USER_MODEL` / `get_user_model()`, не `auth.User`.
- Аутентификация — встроенная: `LoginView`/`LogoutView` из `django.contrib.auth` плюс своя вьюха `signup` (форма `SignUpForm` на базе `UserCreationForm` с выбором роли и автовходом после регистрации). Маршруты — в `accounts/urls.py` под префиксом `/accounts/`.
- Шаблоны лежат в `accounts/templates/`: `base.html`, `home.html` (главная `/`), `registration/login.html`, `registration/signup.html`, а также страницы ошибок `403.html`/`404.html` (лежат в корне `accounts/templates/`, чтобы их находил загрузчик; видны при `DEBUG=False`, наследуют `base.html`). `base.html` — адаптивный навбар Bootstrap с `navbar-toggler`/`collapse` (сворачивается на телефоне) и подсветкой активного раздела по `request.resolver_match.url_name`; для роли student — ссылки «Мои курсы» и «Статистика». Флеш-сообщения (`django.contrib.messages`) рендерятся здесь как `alert-dismissible` с иконкой по уровню (success ✓, error/warning ⚠, info ℹ; тег `error` → класс `danger`). Favicon — инлайновый SVG data-URI в `<head>` (без настройки статики). Внизу — общий футер; страница тянется на всю высоту через flex. Поля форм размечены вручную под Bootstrap-классы (`form-control`, `is-invalid`), а не через `{{ form }}` — при добавлении полей следовать этому стилю.
- Главная (`HomeView` в `accounts/views.py`, контекст строится по роли; модели курсов импортируются внутри метода во избежание связанности): гость — описание сервиса, приглашение зарегистрироваться и до 6 курсов с числом карточек; ученик — активные записи с прогресс-барами и кнопкой «Начать»/«Продолжить», отдельно завершённые (с «Пройти заново»), ссылка на каталог; создатель — его курсы со счётчиками записанных и завершивших, кнопка «Создать курс».
- Статистика ученика (`StudentStatsView`, `/courses/stats/`, только student): активных/завершённых курсов, всего выучено слов (сумма `learned_cards_count` по всем записям), число ответов за последние 7 дней (по логу `AnswerLog`). `AnswerLog` (courses/models) — по одному ряду на каждый ответ (`student`, `enrollment`, `is_correct`, `answered_at`), пишется в `train_answer`; для активности во времени, тогда как суммарные счётчики живут в `Enrollment`.
- Статистика создателю на странице его курса (`CourseDetailView`, ветка `is_author`): записано учеников, прошли хотя бы раз (`ever_completed=True`), всего прохождений с повторными (`Sum(completions_count)`).
- Поиск по каталогу (`CourseListView`): GET-параметр `q`, регистронезависимое вхождение по названию. SQLite не сворачивает регистр кириллицы в `LIKE`/`icontains`, поэтому сопоставление делается в Python (`title.lower()`), а queryset сохраняется через `filter(pk__in=...)`.
- Курсы: `Course` (название, описание, автор — FK на пользователя) и `Card` (слово/перевод, FK на курс, каскадное удаление). CRUD — классовые вьюхи в `courses/views.py`; права через миксины там же: `CreatorRequiredMixin` (создание — только роль creator) и `CourseAuthorRequiredMixin` (правка/удаление курса и карточек — только автор; переопределяет `get_course()`). Ученикам страница курса показывает карточки без переводов (`show_translations` в контексте), а список курсов — колонку статуса их записи. После добавления карточки редирект обратно на форму добавления. В списках используется аннотация `card_count` во избежание N+1.
- Запись на курсы: `Enrollment` (ученик+курс с `UniqueConstraint`, статус active/completed/abandoned; поля-счётчики `answers_correct`/`answers_wrong` и история прохождений `completions_count`/`ever_completed`). Записываться могут только ученики (вьюха `enroll`, POST). Повторная запись после ухода не создаёт дубликат — та же запись переводится в active. «Покинуть курс» (кнопка на странице курса) ставит abandoned, запись не удаляется. Страница «Мои курсы» (`/courses/my/`) — только для роли student; кнопка действия зависит от состояния записи: active без прогресса — «Начать», active с прогрессом — «Продолжить» (обе на тренировку), abandoned — «Начать» (POST на `course_restart`, сброс), completed — «Пройти заново» (GET на `course_restart` → страница подтверждения). Аннотация `progressed_count` (число направлений с level>0) отличает «есть прогресс» без N+1; для страниц вне списков есть свойство `Enrollment.has_progress`.
- `course_restart` (`/courses/<pk>/restart/`, только student): GET — страница подтверждения `course_confirm_restart.html` (для завершённого курса), POST — сброс всех уровней в 0, статус в active, очистка сессии тренировки, редирект на train. Поля `completions_count`/`ever_completed` при сбросе НЕ трогаются. Завершение курса (`_check_course_completed`) при переходе в completed увеличивает `completions_count` и ставит `ever_completed=True`.
- Тренировка (`/courses/<pk>/train/`), система Лейтнера, двустороннее заучивание: единица — объект `CardProgress` (запись+карточка+направление, уникальны втроём; направления `word_to_translation` / `translation_to_word`, по два объекта на карточку — создаются при первом старте, для старых данных — data-миграцией 0006). Тренировка сквозная на весь курс, без порций: в очередь (`_build_queue`) попадают ВСЕ направления с уровнем < `MAX_LEVEL` (0–`MAX_LEVEL`, сейчас 2). Направление «проходит заход» после `LEARNED_STREAK` (2) верных подряд: уровень сохраняется в БД сразу (без ошибок в заходе +1, была ошибка — 0); достигшее MAX_LEVEL фиксируется и больше не предлагается, остальные — в конец очереди на новый заход. Благодаря уровням в БД при следующем входе тренировка продолжается с текущего места. Верный ответ без завершения захода — в конец очереди, неверный — сброс счётчика и возврат через 2–3 позиции. Пустая очередь → проверка завершения (`_check_course_completed`): все объекты записи (карточки × 2) на MAX_LEVEL → статус completed и поздравительный экран в `train_summary.html` (там «карточек выучено X из M» и один показатель — процент правильных ответов, `accuracy_percent`; цвет: зелёный ≥80, жёлтый 50–79, коричневый <50); иначе очередь пересобирается (подхватывает новые карточки). Счётчики ответов — поля `Enrollment.answers_correct`/`answers_wrong`, инкрементятся на каждый ответ в БД и накапливаются между заходами. Прогресс-бар в шапке тренировки — доля выученных направлений по всему курсу (`learned_progress_count`/`total_progress_count`), только полоска, без цифр. Прогресс курса (страница курса, «Мои курсы») — ПО КАРТОЧКАМ: карточка выучена, когда оба направления на MAX_LEVEL (`learned_cards_count`, знаменатель — число карточек; «выучено N из M»). Состояние текущего прохода (очередь, стрики) — в `request.session['training_<enrollment_id>']` (с полем `v` — версия формата, старая отбрасывается); PRG-цикл `train` → `train_answer` (POST) → `train_feedback`. Вопрос/варианты строятся по направлению (`_question_for`, `_build_choices`: правильный ответ + до 3 переводов либо слов других карточек); варианты передаются скрытыми полями `choices` для подсветки на странице результата. После верного ответа — автопереход через 0.7 с с полоской-индикатором (инлайн-JS, без паузы по наведению, `<noscript>`-ссылка «Далее»); после неверного — только кнопка «Далее».
- Флеш-сообщения (`django.contrib.messages`) выводятся в `base.html`.
- Выход из аккаунта — только POST-формой (требование Django 5+); ссылки `<a href>` на logout работать не будут.
- Тексты интерфейса и `verbose_name`/labels моделей и форм — на русском.
